# 学習方針

## 基本方針
- 完璧を目指さず、55点合格を最短で取る
- 理解 > 暗記。ただし法規は暗記も必要
- 弱点を放置しない。必ず `mistakes/weak_points.md` に記録する
- 1回で全部理解しようとしない。繰り返しで定着させる

---

## ツール役割分担

| ツール | 用途 |
|--------|------|
| **GitHub** | 長期資産（ノート・弱点・テンプレ・週次レビュー） |
| **Notion** | 日次運用（今日やること・雑メモ・下書き） |
| **Claude** | 解説・弱点分析・プロンプト活用 |

**二重管理しない。同じ内容を両方に書かない。**

---

## 知識の置き場（確定ルール）

Wiki は「条文×過去問クロスリファレンス」という**構造に最適化された資産**であり、
機械・電力の計算問題はその構造に乗らない。無理に同居させると Wiki の強みが薄れる。
したがって Layer 1（知識ベース）は **Wiki と `notes/` の2箇所に分担**する。

| 内容 | 置き場 |
|---|---|
| 法規（条文・過去問クロスリファレンス） | **denken-wiki** |
| 理論の科目別まとめ | **denken-wiki** の `theory/` |
| **科目をまたぐ物理法則**（Φ→e、ローレンツ力、磁気回路 …） | **`notes/clusters/*.md`** |
| 機械・電力の機器知識 | **`notes/<科目>.md`** |
| 弱点記録 | **`mistakes/weak_points.md`** |
| テスト記録（数値） | **`data/records.json`**（`sr-record.py` が唯一の writer。手編集禁止） |

詳細な判定フローは [`notes/README.md`](../notes/README.md)。

### なぜ「クラスタ」を科目より上に置くのか

記録データ上、失点は**科目ではなく物理法則で固まっている**。
要復習（ng / risky）25件のうち16件（64%）が磁気クラスタ（電磁誘導・磁界・インダクタンス・ローレンツ力）。
理論の「電磁誘導」と機械の「変圧器の誘導起電力」は同じ `e = -N dΦ/dt` であり、
科目別に分けると同じ穴を2回掘ることになる。

**クラスタは弱点が溜まってから作る。** 空のフォルダ構造を先に作らない。
目安：同じ物理法則の ng / risky が3件を超えたら1本立てる。

## 1日の理想の流れ

1. **学習前**：Notionで今日やることを3つだけ決める
2. **学習中**：Notionに雑にメモしてよい
3. **学習後**：残す価値があるものだけGitHubへ追記
4. **週末**：GitHubのノート・弱点集・週次レビューを整える

---

## 弱点管理ルール

弱点は **必ず** `mistakes/weak_points.md` に残す。  
弱点は点数と成長に直結する資産だから。

記録フォーマット：
- 何が弱いか
- どこで間違えたか
- 正しくはどう考えるか
- 次回どう防ぐか

---

## コミット方針

- 1変更1コミット
- メッセージは具体的に（例：「理論ノートに交流回路を追記」）
- 完成品でなくてよい。3行でも残す
