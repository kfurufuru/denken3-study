# 振り返りログ（エージェントの手戻り・判断ミス）

エージェントが作業を終える前に、ユーザーに言われなくても書く。書き方とルールは `CLAUDE.md` の「振り返り」を参照。
セッション開始時に `scripts/retro_open.py`（SessionStart hook）が「効果未確認」を表示する。

- 1件 = 1つの手戻り・判断ミス・ユーザーからの指摘。
- **確認条件**には「次にどんな作業が来たら、何が起きれば効いたと言えるか」を書く。確認できないものは書かない。
- 該当する作業をしたら、結果を書いて「確認済み」へ移す。効かなかったら対策を書き換えて未確認に残す。
- 同じ種類が2回目なら、`scripts/check_*.py` で検出できないか考え、できなければ `CLAUDE.md` に1行足す。

### R-002 置き場所を聞かずに作り、翌日移した（#38 → #40）
- 起きたこと: Git ガイドをトップのタブに置き、翌日に学習法ページのリンクへ移した。PR が2本になった。
- 原因: 「タブは場違い」と自分で指摘しながら、置き場所を確認せずに作った。
- 対策: 自分で違和感を指摘した設計判断は、作る前に一言聞く（1回目なので CLAUDE.md には足していない）。
- 確認条件: 次にページや導線を追加する作業で、置き場所を作る前に確認したか。同種の手戻りが再発したら CLAUDE.md に1行足す。

### R-004 2か所から書く場合の衝突を「数秒以内に重なったときだけ」と言い切った（2026-11-15）
- 起きたこと: クラウドのセッションからも records.json を書けるようにする提案で、衝突は数秒以内に重なったときだけと説明した。実装を読むと、`sr-record.py` は手元の records.json に追記して commit してから pull していた。手元が古ければ、時間が離れていても配列の末尾どうしが衝突し、記録が push されずに止まる（使い捨ての bare リポジトリで再現）。
- 原因: 書き込みの順序（読む→追記→commit→pull→push）を読まずに、push 直前の pull だけを見て性質を断定した。
- 対策: `sr-record.py` に「本実行では読む前に pull する」を足した（secretary-portal #2218）。改修版では古い clone からの記録も両方 origin に届いた。
- 確認条件: 次に PC とクラウドの両方で記録した日に、後から書いた側が `[WARN] git pull 失敗` を出さずに `[OK] origin へ push 完了` になったか。

### R-005 構文エラーのまま commit した（#47 の 1382179 → d3954af）
- 起きたこと: `check_site.py` の改行の置換を、heredoc の中の Python で文字列置換して書いた。`\r\n` が本物の改行になり、構文エラーになった。検査の出力を見る前に、同じコマンドの中で commit まで流した。
- 原因: 置換の結果を確かめる段（`py_compile`）と commit を1つのコマンドにまとめた。エスケープの多い置換を、文字列置換で書いた。
- 対策: エスケープ（`\r` `\n` `\\`）を含む変更は Edit で書く。`python -m py_compile` と検査を通してから、別のコマンドで commit する。
- 確認条件: 次に `scripts/` か `update_dashboard.py` を変える作業で、構文エラーを直すだけの commit が出なかったか。

### R-006 誤答の解説で、核心が出るまでに3回聞き直させた（2026-11-22）

- 原因: 規則を先に書き、その元になる一般的な式から導かなかった。似た用語を区別する確認をしなかった。

- 確認条件: 次に誤答の写真や「わからなかった」が来たとき、最初の応答のあとにユーザーが原理や用語の区別（「A？B？」「〜だから？」）を聞き返さずに済んだか。聞き返しが出たら、どの項目が抜けたかを書いて対策を直す。

### R-001 確認ルールを2回書き直した（#41 → #42）
- 起きたこと: 学習内容の PR を「ユーザーが Files changed で見る」ルールにしたが、ユーザーは差分を読まないため1日で形骸化し、クイズ方式に書き直した。
- 原因: ユーザーが実際にどう動いているかを聞かずに、人に頼る確認を設計した。
- 対策: `CLAUDE.md`「書き込みの持ち主」のクイズ方式（#42）。人に頼る確認を作る前に、その人の実際の行動を聞く。
- 確認条件: 次に `notes/` `mistakes/` `data/` `zukai/` の数値・条文を変える PR で、マージ前にクイズを出し、ユーザーが答えたか。答えずに「マージして」だけが返ったら効いていない。
- 結果（2026-11-22, #50）: マージ前にクイズを3問出し、ユーザーは「マージして」ではなく2問に答えた。地絡時の健全相の対地電圧で食い違いが見つかったが、PR の値は導出（地絡相が大地電位になり、健全相の対地電圧＝線間電圧）で確かめて正しく、ユーザーの誤答として DE-01 に記録した。クイズが学習内容の確認として働いたので、効いたと判断する。
