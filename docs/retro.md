# 振り返りログ（エージェントの手戻り・判断ミス）

エージェントが作業を終える前に、ユーザーに言われなくても書く。書き方とルールは `CLAUDE.md` の「振り返り」を参照。
セッション開始時に `scripts/retro_open.py`（SessionStart hook）が「効果未確認」を表示する。

- 1件 = 1つの手戻り・判断ミス・ユーザーからの指摘。
- **確認条件**には「次にどんな作業が来たら、何が起きれば効いたと言えるか」を書く。確認できないものは書かない。
- 該当する作業をしたら、結果を書いて「確認済み」へ移す。効かなかったら対策を書き換えて未確認に残す。
- 同じ種類が2回目なら、`scripts/check_*.py` で検出できないか考え、できなければ `CLAUDE.md` に1行足す。

## 効果未確認

### R-001 確認ルールを2回書き直した（#41 → #42）
- 起きたこと: 学習内容の PR を「ユーザーが Files changed で見る」ルールにしたが、ユーザーは差分を読まないため1日で形骸化し、クイズ方式に書き直した。
- 原因: ユーザーが実際にどう動いているかを聞かずに、人に頼る確認を設計した。
- 対策: `CLAUDE.md`「書き込みの持ち主」のクイズ方式（#42）。人に頼る確認を作る前に、その人の実際の行動を聞く。
- 確認条件: 次に `notes/` `mistakes/` `data/` `zukai/` の数値・条文を変える PR で、マージ前にクイズを出し、ユーザーが答えたか。答えずに「マージして」だけが返ったら効いていない。

### R-002 置き場所を聞かずに作り、翌日移した（#38 → #40）
- 起きたこと: Git ガイドをトップのタブに置き、翌日に学習法ページのリンクへ移した。PR が2本になった。
- 原因: 「タブは場違い」と自分で指摘しながら、置き場所を確認せずに作った。
- 対策: 自分で違和感を指摘した設計判断は、作る前に一言聞く（1回目なので CLAUDE.md には足していない）。
- 確認条件: 次にページや導線を追加する作業で、置き場所を作る前に確認したか。同種の手戻りが再発したら CLAUDE.md に1行足す。

### R-003 学習以外の作業が続いた（2026-10-11〜13）
- 起きたこと: 3日で PR 4本（#38, #40, #41, #42）、すべて仕組みの整備。試験の点数につながる作業はゼロ。
- 原因: 仕組みの手入れは手応えがあり、エージェントも依頼どおりに続けた。
- 対策: 仕組みの作業が終わったら、`mistakes/weak_points.md` か過去問に戻ることを最終報告で提案する。
- 確認条件: 次のセッションで、学習内容（弱点・過去問・ドリル）の作業が行われたか。
