# zukai-drill — 描き直して身につける図解ドリル

## なぜこの形にするのか

完成した図を読むだけでは「わかった気」になるだけで、試験でベクトル図や等価回路を自分で描けるようにはならない。自分で描いて（思い出して）から答え合わせするほうが記憶に残る（生成効果・想起練習）。だからこのスキルの出力は「解説ページ」ではなく**ドリル**にする。完成図は最初は畳んで隠しておき、学習者が紙に描いたあとで開いて照合する。

もう1つの理由は誤りのリスク。きれいな図は間違っていても正しく見えてしまう。このリポジトリでは、AIが作った内容の誤りを直すコミット（#30、#32）が実際に出ている。だから図に載せる数値・角度・向きは、**描く前に計算で確かめる**。

## 入力

次のどれかを受け取る。足りない情報は推測で埋めず、学習者に聞く。

- `mistakes/weak_points.md` の項目名（例：「B種接地工事の接地抵抗」）
- 過去問の番号と、どこで間違えたか
- 概念名（例：「同期発電機の電機子反作用」「Δ-Y変換」）

弱点の項目が指定されたら、まず `mistakes/weak_points.md` の該当部分を読む。「どこで間違えたか」が、空欄にする場所を決めるいちばんの手がかりになる。関連する説明が `notes/` や `data/theory-guide.md` にあれば、そちらも読んで用語と記号をそろえる。

## 手順

1. **図にする対象を1つに絞る**：試験で描けると得点に直結するもの（ベクトル図・等価回路・系統図・計算の流れ図・特性曲線など）を1枚選ぶ。図を何枚も並べたくなったら、論点が多すぎるサイン。
2. **先に検算する**：図に載せる数値・位相角・電流の向き・不等号の向きは、Python などで実際に計算して確かめる。計算の結果と図が食い違わないよう、SVG の座標は計算値から決める（ベクトルの長さや角度を目分量で描かない）。
3. **根拠を確かめる**：法規の条文番号・規定値、公式の適用条件は、リポジトリ内の記述（weak_points、notes、denken-wiki への言及）と照らし合わせる。確信が持てない点は本文に「⚠ 要確認：〜」と書いて残す。条文番号やもっともらしい数値を推測で埋めることはしない。黙って間違えるより、確認が必要だと示すほうがずっと安全だから。
4. **空欄を決める**：学習者が間違えた箇所、または取り違えやすい箇所を空欄にする。目安は3〜5か所。全部を空欄にすると手が止まり、少なすぎると思い出す練習にならない。
5. **HTML を書く**：下の構成で `zukai/<科目>-<テーマ>.html` に保存する（例：`zukai/houki-b-shu-setchi.html`）。
6. **自己チェック**：書き終えたら、完成図・空欄の答え・検算の数値が3つとも一致しているか見直す。

## ページ構成（この順番を守る）

順番が大事。完成図が先に目に入ると、思い出す練習にならないから。

1. **ヘッダー**：テーマ名、元になった弱点や過去問、作成日。
2. **この図で答えられるようになること**：問いを1〜2行で書く（例：「なぜ R_B に上限があるのか、混触時の電流の通り道で説明できる」）。
3. **描き直し課題**：「紙に〇〇を描いてから下に進む」という指示と、描くときに入れる要素のリスト。
4. **空欄版の図**：SVG に番号付きの空欄（①②③…）。各空欄の答えは `<details>` で個別に開けるようにする。
5. **完成図**：`<details>` で畳んでおく。開くと全部が埋まった図が出る。
6. **検算**：式に数値を代入する過程を1行ずつ書く。最終値だけでなく途中の値（V、L、I₁ など）も示す。最終値が偶然合うケースを見抜けるように、条件を変えた検算例を1つ入れると効果が大きい。
7. **自己採点チェックリスト**：描いた図に何が入っていれば合格かを3〜5項目で示す。
8. **根拠と要確認事項**：条文・公式の出典と、⚠ 要確認の一覧。なければ「なし」と書く。
9. **戻るリンク**：`../index.html` へのリンクと、元になった弱点（`mistakes/weak_points.md`）への案内。

## HTML の決まりごと

- 外部スクリプトは使わず、図はインライン SVG で描く。リポジトリは GitHub Pages で公開されているので、1ファイルで完結させる。
- 配色は既存ページ（`sq3r.html`）の CSS 変数（`--bg #0f172a`、`--bg2 #1e293b`、`--accent #38bdf8`、`--text #e2e8f0`、`--yellow`、`--red`、`--green`）に合わせる。フォントは Google Fonts の Inter と Noto Sans JP。
- スマートフォンで見ることが多い。SVG には `viewBox` を付けて `width:100%` で縮むようにし、横スクロールを出さない。図中の文字は縮んでも読める大きさ（viewBox 幅 640 前後なら 14px 以上）にする。
- 空欄は図中で目立たせる（点線の枠と番号）。正解の文字は、空欄版の SVG には入れない（DOM に答えが入っていると、ページ内検索などで答えが見えてしまうため）。

## 作ったあと

- 学習者には、ページの場所と「紙に描いてから開く」使い方を一言で伝える。
- 作成中に weak_points.md の誤りや抜けに気づいたら、勝手に書き換えずに指摘する。
